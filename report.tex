% ---- Introduction ----
\section{Introduction}

The goal of this project is to predict the market price of houses based on various attributes. The market price ($y$) of any house depends on many factors ($x_1, x_2, \dots, x_N$) including location, view, surrounding, etc. As a more adequate price is set, the smoother (and fairer) the selling process goes. Therefore, the goal is to predict/set the price of the house in accordance with those parameters.

The dataset for this problem contains 506 instances with 13 attributes each, including numerical and categorical data such as per capita crime rate (CRIM), average number of rooms (RM), and nitric oxides concentration (NOX).

To solve this, we employ the **Normal Equation** method for linear regression. The Normal Equation provides an analytical solution to the least squares problem, minimizing the cost function $J(\beta) = ||X\beta - y||^2$. The solution is given by:
\[ \beta = (X^T X)^{-1} X^T y \]
This method yields the exact optimal coefficients that minimize the residual sum of squares on the training data.

% ---- Method ----
\section{Method}

We implemented the solution in Python using the \texttt{numpy} library for matrix operations and \texttt{pandas} for data handling. The implementation follows these steps:

\subsection{Data Processing}
The dataset is loaded from \texttt{Problem2\_Dataset.csv}. We extract the features and the target variable (MEDV). The data is then split into a training set (80\%) and a testing set (20\%). An intercept term (a column of ones) is added to the feature matrix to account for the bias term $a_0$.

\subsection{Model Training}
We compute the coefficients $\beta$ using the Normal Equation:
\[ \beta = \text{np.linalg.inv}(X_{train}^T X_{train}) @ (X_{train}^T y_{train}) \]

\subsection{Evaluation}
We predict the prices on the test set using $y_{pred} = X_{test} \beta$ and calculate the Root Mean Squared Error (RMSE). To ensure the stability of our results, we repeat the training and testing process 100 times with random splits and report the mean and standard deviation of the RMSE and coefficients.

% ---- Discussion ----
\section{Discussion}

Using the normal equation is mathematically correct, but it is often a poor practical choice. Below is a precise, engineering-oriented explanation of why it can be problematic, and when other methods should be used instead.

\subsection{Why the Normal Equation is Problematic}

\subsubsection{Matrix Inversion is Expensive}
The Normal Equation requires computing $\beta = (X^T X)^{-1} X^T y$. If $p$ is the number of features:
\begin{itemize}
    \item Computing $X^T X$ takes $O(np^2)$.
    \item Inverting the $p \times p$ matrix takes $O(p^3)$.
\end{itemize}
This works for small $p$, but becomes infeasible for large feature sets (e.g., $p = 10^4$).

\subsubsection{Numerical Instability (Ill-conditioning)}
If features are highly correlated, poorly scaled, or nearly linearly dependent, then $X^T X$ becomes ill-conditioned.
\begin{itemize}
    \item Small numerical errors cause large errors in $\beta$.
    \item Inversion amplifies floating-point noise.
\end{itemize}
This is extremely common in real-world data.

\subsubsection{Fails Completely when $X^T X$ is Singular}
The inverse does not exist when features are linearly dependent or when $p > n$ (more features than samples). This is typical in high-dimensional ML (text, image, genomic features). In these cases, the Normal Equation simply cannot be used.

\subsubsection{Memory Constraints}
You must store the entire $X$ and $X^T X$ in memory. This blocks streaming data, online learning, and large datasets that do not fit in RAM.

\subsubsection{No Regularization by Default}
The Normal Equation minimizes training error only, which leads to overfitting. Regularization requires modifying the equation (Ridge/Lasso), which complicates inversion further.

\subsection{When the Normal Equation is Acceptable}
Use it only when \textbf{ALL} of the following hold:
\begin{itemize}
    \item \textbf{Small dataset}: Inversion is cheap.
    \item \textbf{Low feature count ($p < 1000$)}: $O(p^3)$ is manageable.
    \item \textbf{No multicollinearity}: Ensures stable inversion.
    \item \textbf{Well-scaled features}: Better conditioning.
    \item \textbf{Educational / theoretical work}: Clear closed-form solution.
\end{itemize}
Example: teaching linear regression, quick prototypes, or sanity checks.

\subsection{Better Alternatives}

\subsubsection{A. SVD / Pseudoinverse}
Formula: $\beta = X^+ y$, where $X^+$ is the Moore–Penrose pseudoinverse via SVD.
\begin{itemize}
    \item \textbf{Use when}: $X^T X$ is singular/ill-conditioned, $p > n$, or numerical stability is needed.
    \item \textbf{Why better}: Handles rank deficiency, avoids explicit inversion of $X^T X$, industry-standard approach.
\end{itemize}

\subsubsection{B. QR Decomposition}
Formula: $X = QR$, solve $R\beta = Q^T y$.
\begin{itemize}
    \item \textbf{Use when}: Medium-sized problems, need good numerical stability, batch least squares.
    \item \textbf{Why better}: Avoids forming $X^T X$, more stable than Normal Equation.
\end{itemize}

\subsubsection{C. Gradient Descent / SGD}
Iterative update: $\beta_{k+1} = \beta_k - \eta \nabla J$.
\begin{itemize}
    \item \textbf{Use when}: Large $n$, streaming data, online learning, memory constraints.
    \item \textbf{Why better}: No matrix inversion, scales to millions of samples, works easily with regularization.
\end{itemize}

\subsubsection{D. Ridge Regression}
Formula: $(X^T X + \lambda I)\beta = X^T y$.
\begin{itemize}
    \item \textbf{Use when}: Multicollinearity exists, overfitting is a concern.
    \item \textbf{Why better}: Guarantees invertibility, improves generalization.
\end{itemize}

\subsection{Practical Decision Table}
\begin{table}[H]
\centering
\begin{tabular}{|l|l|}
\hline
\textbf{Situation} & \textbf{Recommended Method} \\
\hline
Small, clean data & Normal Equation \\
Correlated features & Ridge / SVD \\
$p > n$ & SVD \\
Large dataset & SGD \\
Streaming data & SGD \\
Production ML & SGD / SVD \\
Numerical robustness required & QR / SVD \\
\hline
\end{tabular}
\caption{Method Selection Guide}
\end{table}

\subsection{Takeaway}
The Normal Equation is mathematically elegant but computationally fragile; in real systems it is replaced by SVD, QR, or gradient-based methods depending on scale, conditioning, and deployment constraints.
